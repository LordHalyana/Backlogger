Decisions

1, 2 and 4 chosen on 20 October. 3, 5 and 6 still need a yes before the ticket is closed.

1 · Layout

Chosen: A with reader

Full-width thread with docked composer; clicking a comment opens a reader pane and the thread narrows to one-line rows. Shown at the top of this page.

2 · Long history (reopens an approved decision)

Chosen: open on the newest page

Oldest-first pages of 50 hide the newest 70 of 120 comments, and in A the composer sits below comments you cannot see. Suggest loading the newest page first with "Load older comments" at the top, still reading oldest to newest. This changes the pagination direction in the approved comment API decision.

3 · Delete confirmation

Recommend inline (in the reader)

Confirming inside the comment keeps your place in a long history and focus moves to the next comment. B uses the app's modal dialog.

4 · Leaving with a draft

Chosen: ask before discarding

The alternative silently keeps the draft in memory, but it is lost on reload anyway, so it promises more than it keeps.

5 · Edit conflict

Recommend as shown

Saved version and your edit side by side. Continue editing on the current version, copy your edit, or discard it. Nothing overwrites the saved version without a fresh save.

6 · Tab label

Recommend: Comments (total) •

Total count, plus a dot while a comment draft is unsaved. Description gets the same dot for unsaved description edits.
